# Program Brief

## Purpose

Photography portfolio for Claire Thomas with a small authenticated content manager. Public pages remain lightweight HTML/CSS/JS; Vercel Functions provide authentication, Cloudinary-backed content, and signed uploads. Public image delivery also supports optional per-item Google Drive file IDs while Cloudinary is being repaired or migrated.

## Important Files And Boundaries

- For non-commerce architecture, hosting, storage, authentication, or production-versus-local state, read `APP_REFERENCE.md`. For setup, deployment, content edits, recovery, or troubleshooting, read `APP_OPERATIONS.md`.

- `site.js`: shared navigation, gallery data, detail-page rendering, lightbox behavior, and optional Google Drive image resolution.
- `cms-loader.js`: loads `/api/content`, then renders through `site.js`; bundled gallery data remains the public fallback.
- `google-drive-manifest.json`: local, uncommitted photo-ID to Drive-file-ID map. Version 5 contains 246 mappings with audit details. October 2 inspection found the manifest absent from production and live image delivery still Cloudinary-backed; mapping accuracy requires separate verification.
- `admin.html`, `admin.css`, `admin.js`: website-only portfolio editor at `/admin.html`.
- `api/`: Vercel Functions for public content, admin sessions, content saves, and signed Cloudinary uploads.
- `content/portfolio.json`: exact bundled fallback and current CMS snapshot (revision 187, 8 albums, 246 photos).
- `scripts/create-admin-credentials.mjs`: creates the ignored local credential handoff and environment file.
- `scripts/configure-vercel-admin-env.mjs`: applies the admin and Cloudinary secrets to Vercel without printing them.
- `scripts/seed-portfolio-content.mjs`: idempotently seeds the Cloudinary raw JSON content asset.
- `styles.css`: shared site layout and page-specific styling.
- `*.html`: individual entrypoints that set `body[data-page]` and load the shared assets.
- `prints.html`: print-shop landing page. The actual checkout/fulfillment URL is configured in `printShopConfig.shopUrl` in `site.js`.
- `Place/`, `The Natural World/`, `Protests/`, `Shapes & Shadows/`, `Commissioned Work/`: image assets. Treat as content, not app logic.
- `scripts/`: utility scripts for Cloudinary upload workflows.
- `driveFileId` on a photo item opts that image into Google Drive thumbnail delivery; its existing Cloudinary `publicId` remains available as fallback. Drive files must be publicly viewable.
- `scripts/gelato-products.mjs`: CMS-authoritative dry-run/reconcile, template validation, stale-product audit, and resumable product creation for Gelato + Shopify.
- `scripts/portfolio-print-sync.mjs`: bounded one-shot public-CMS sync runner; it locks, persists pending/successful CMS revisions, and invokes reconcile only when needed.
- `api/admin/shop-sync.js`: authenticated, CSRF-protected one-time GitHub Actions dispatcher used by the admin **Sync shop** button.
- `.github/workflows/portfolio-shop-sync.yml`: serialized, manually dispatched catalog reconcile plus strict audit; there is no recurring catalog timer.
- Missing remote products are recreated even when an obsolete Gelato ID remains in local state.
- Reconciliation keeps products hidden while artwork media is repaired, then sets Shopify `ACTIVE` and explicitly publishes to the Online Store. Strict audit fails any expected product that is active but not Online-Store-published. Repair stalled drafts with `node scripts/gelato-products.mjs --execute --repair-created --repair-batch-photos 1`; do not rely on Gelato visibility alone.
- `.gelato-product-manifest.json`, `.gelato-product-state.json`, `.gelato-stale-products.json`: ignored local artifacts generated by the Gelato batch workflow.
- `.portfolio-print-sync-state.json`, `.portfolio-print-sync-content.json`, `.portfolio-print-sync.lock`: ignored poller state, fetched CMS snapshot, and overlap lock.
- `scripts/capture-shopify-credential.mjs`: reads one copied Shopify app credential at a time and writes the ignored mode-600 `.env.shopify.local` without printing it.
- `.vercel/`: deployment linkage/config created by Vercel CLI.

Keep content image directories and generated deployment metadata out of scope unless the task specifically requires them.

## Run And Verify

- Install dependencies: none required.
- Full checks: `npm run check`
- Local application: load `.env` and `.env.local`, then run `vercel dev --listen 8080 --yes`.
- Admin: `http://localhost:8080/admin.html`
- For navigation changes, verify the sidebar link state and destination page.
- For layout changes, verify both desktop and narrow/mobile widths.

## Current Operating Brief

- Current user goal (September 30, 2026): first pass a single existing-product E2E pilot before deciding/deploying shop simplification. See `EXISTING_PRODUCT_PILOT.md`. Pilot is `the-natural-world-2` / Shopify `10549112668344`; currently Draft, unpublished, no media. Do not run a catalog-wide writer or publish incomplete products. New-photo planner remains offline and unconnected to admin; preserve existing setup pending pilot evidence and explicit scoped repair approval.
- Prefer small, attributable edits in `site.js`, `styles.css`, and the relevant HTML entrypoint.
- Portfolio content edits should use `/admin.html`: add/delete/rename/reorder albums; nest an album under a section or another album; upload/delete/restore/reorder photos; edit captions; toggle per-photo print availability.
- CMS deletion is recoverable: photos move to Trash and Cloudinary originals are preserved.
- `printEnabled` on each photo is the sole catalog inclusion control. Commissioned Work and new admin uploads start false. The CMS never calls Shopify or Gelato; `scripts/gelato-products.mjs --reconcile` consumes the public CMS snapshot and performs the separate print-product synchronization.
- Admin saves use an authenticated Cloudinary resource version for concurrency checks. Public reads remain CDN-cacheable and fall back to `content/portfolio.json` if the CMS asset is unavailable.
- New sections should usually be added as a new `*.html` file plus a small `render...` branch in `site.js`.
- Commissioned Work uses Cloudinary IDs `commissioned-work/1` through `commissioned-work/23`; upload it with `scripts/upload-commissioned-work-to-cloudinary.sh`.
- Keep the visual language minimal and consistent with the existing site unless explicitly asked to redesign it.
- Print sales use an external handoff to `shop.clairethomas.art`. Every gallery/lightbox link opens the photograph's canonical Fine Art product page directly.
- The live Horizon theme includes `shopify-theme-overrides/ct-product-consolidation.liquid` before `</body>`. It shows each Fine Art photograph once in storefront and predictive-search grids, requires the contact email, and does not expose retired Canvas or Framed choices. San Francisco 93 is the narrow Gelato-only gallery pilot: its original artwork media is hidden from the product gallery and linked separately for reference; other products retain the two-image layout until the pilot is approved.
- Shopify reconcile adds one stable-marker Cloudinary artwork image to every managed product. Newly created or repaired products remain hidden as Shopify drafts until that artwork is `READY` and first in the media list. Each Fine Art Shopify variant is then bound to its exact Gelato mockup by matching the Shopify SKU to the Gelato variant ID; Gelato `externalId` is not used for this mapping. The Horizon override shows only the selected size's mockup while retaining the original artwork as a secondary zoomable image. `--strict-audit` reports active keys whose artwork marker, exact mockup binding, or Online Store publication still needs repair.
- The print catalog derives from CMS albums/items with `item.printEnabled === true`, including nested/new albums. Each photograph has one Fine Art Print product with three aspect-ratio-matched sizes. Template validation rejects any vertical variant whose image placeholder is not portrait and any horizontal variant whose placeholder is not landscape. Canvas and Framed products are retired through reversible Shopify archiving and are never recreated. `item.id` is the stable identity; album labels, hierarchy, album/photo order, and descriptions are reconciled as customer-facing metadata. Run `node scripts/gelato-products.mjs --content-file /tmp/claire-live-content.json --reconcile` for a dry-run plan, then add `--execute` only after review.
- Fresh workflow runners enrich Gelato records with Shopify product status. Shopify-archived products are excluded from reconcile and strict audit, while Gelato products still waiting for a Shopify ID remain pending and resumable. A `publishing_error` Gelato draft is recovered during normal reconcile: its mapped Shopify product is archived first when present, the failed Gelato record is deleted, and the same stable photo key/handle is recreated; ordinary active or archived Shopify products are never deleted.
- Create or resume the public catalog with `node scripts/gelato-products.mjs --reconcile --execute --content-file /path/to/cms-snapshot.json`. Shopify credentials load from ignored `.env.shopify.local`; an explicit `SHOPIFY_ADMIN_ACCESS_TOKEN` wins, otherwise the script requests a short-lived client-credentials token using `SHOPIFY_CLIENT_ID` and `SHOPIFY_CLIENT_SECRET`. The installed app requires `read_products`, `write_products`, `read_publications`, and `write_publications`; the latter pair prove and set Online Store publication. The ignored state file and stable ID/format tags prevent duplicate creation, and API throttling is retried with exponential backoff.
- On resume, pending Gelato products in `created`, `publishing`, or `publishing_queued` are polled until Shopify external IDs appear. An `active` Gelato response without an exact Shopify `externalId` remains pending. Once mapped, each product is moved to Shopify Draft, repaired, and activated; it should not be treated as blocked while still publishing.
- Canonical-handle assignment may recover a Shopify-only orphan only when its `photo-id`, format, catalog-version, and `claire-thomas` identity tags exactly match the incoming managed product and it is already Draft or is an unusable Active shell with zero media and every variant unbound. The blocker is archived under a deterministic history-preserving handle, then assignment is retried once. Usable Active, differently tagged, or incompletely tagged blockers fail closed and are never mutated.
- Reconcile drains and repairs an existing pending Gelato batch before requesting any missing products. This prevents a saturated publishing queue from holding one create request in repeated `429` backoff for hours; the bounded continuation creates the remaining products after the queue clears.
- Gelato inventory discovery merges creation-time and update-time pagination in both directions and requires two consecutive identical ID sets because offset pages can otherwise omit tied records. Immediately before every create, Shopify's canonical handle is checked: an existing exact managed identity defers the run for a fresh inventory plan, while any differently tagged owner fails closed. A pre-POST reservation is saved in the workflow cache and suppresses another attempt for two hours after an ambiguous response. JSON `5xx` create responses are never replayed in-process. These guards apply to reconcile, repair, and legacy execute modes.
- Gelato products that remain `created` without a Shopify mapping for two hours are treated as stranded: reconcile deletes that exact Gelato record and recreates the stable catalog key. New creation runs in sequential publishing batches capped at 24 products to avoid saturating Gelato's queue.
- Reconcile removes a Gelato record only after its mapped Shopify product is already archived, deleted, or missing. The Shopify archive is preserved; clearing these retired fulfillment records in restart-safe batches of four prevents the Gelato store quota from blocking current CMS products.
- Malformed non-JSON Gelato gateway responses are retried only when the request is safe or the HTTP status is retryable. Exhaustion exits through the bounded continuation path; an ambiguous successful create response is never replayed in-process.
- Use the admin **Sync shop** button after portfolio changes. It saves pending content and dispatches the serialized GitHub Actions workflow, which runs `node scripts/portfolio-print-sync.mjs --execute` and a strict audit. The CLI remains dry-run by default; failures leave the CMS revision pending. It records a reconciliation contract version, so a release that adds a required repair runs once against the unchanged CMS revision. Each attempt bounds Gelato `429` retries to 48 requests and exits with code 75 for retryable Gelato publishing or Shopify asynchronous media/job/binding timeouts, with at most five self-continuations. Auth, mapping, test, and strict-audit defects do not self-dispatch. This is event-driven recovery for the one button-triggered run, not a recurring catalog timer.
